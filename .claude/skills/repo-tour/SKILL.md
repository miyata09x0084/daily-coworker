# repo-tour — リポジトリを2〜3分の説明動画に

題材リポジトリを、非エンジニア(PM・顧客候補)がドキュメントより速く理解できる日本語説明動画へ変換する。用語は `CONTEXT.md`「リポジトリ説明動画(repo-tour)」セクションが単一の真実源。

**核心原則:**

1. **唯一の承認関門は絵コンテ。** 承認前にコストの発生する生成(画像)・映像化を絶対に行わない。
2. **全自動要約の誤読を本編に持ち込まない。** 理解インタビューで共通認識を確定してから絵コンテを書く。
3. **予算は月¥3,000。** 見積り提示なしに生成へ進まない。超過見込みは承認を求めず中断して報告する。

**パス定義(以下で使う):**

- `RENDERER` = `.claude/skills/repo-tour/renderer`
- `WORKDIR` = `output/videos/<repo名>-<YYYY-MM-DD>/`
- 台帳 = `output/videos/cost-ledger.md`

## 手順

### 0. 前提チェック(毎回・冪等)

1. 題材リポジトリのパスを発話または `/repo-tour <path>` から得る。無ければ質問する。
2. 環境を順に確認し、欠けているものだけセットアップする:
   - `RENDERER/node_modules` が無い → `cd RENDERER && npm install`
   - `~/.config/daily-coworker/.env` が無い → 次を案内する: 「https://aistudio.google.com/apikey でAPIキーを作成し、ターミナルで `mkdir -p ~/.config/daily-coworker && echo 'GEMINI_API_KEY=貼り付け' > ~/.config/daily-coworker/.env && chmod 600 ~/.config/daily-coworker/.env` を実行してください」。キーをチャットに貼らせない。**`scripts/` 配下や リポジトリ内に置いてはならない**(backup-private.sh が private リポジトリへ同期するため漏洩経路になる)。TTS は無料枠で動くが、画像生成はプロジェクトへの課金設定(請求先の紐付け)が必要
3. 台帳を Read して当月累計を把握する。無ければ次の雛形で作成する:

```markdown
# repo-tour — コスト台帳

- 月上限 ¥3,000(1USD=160円の固定換算・安全側)。工程3で「当月累計+見積り」が上限を超えるなら中断する。
- 当月 = 日付列の YYYY-MM が一致する行の実績合計。行は消さない。

| 日付 | 動画 | 画像枚数 | 見積(¥) | 実績(¥) | 当月累計(¥) |
|------|------|---------|---------|---------|------------|
```

### 1. 自動読解(サブエージェント)

読み取り専用サブエージェントに題材リポジトリのパスを渡し、次の形式で返させる:

- **一言でいうと** / **解く困りごと(推定)** / **主要機能(最大5)** / **システム構成(非エンジニア語彙で最大6要素)** / **ペルソナ候補** / **自信のない読解・不明点(最低1件、ゼロは受理しない)**

最後の項目が工程2の質問の種になる。README 不在・読解不能でも中断せず、空レポート+「全項目をインタビューで得る」と宣言して工程2へ。

### 2. 理解インタビュー(grilling型)

観点は5つ固定。1ラウンド3〜5問をまとめて聞き、各問に推奨回答を付ける:

1. **誤読の検出** — 「自動読解ではこう理解したが正しいか」を1項目ずつ突きつける
2. **視聴者の具体化** — この動画を見せる相手は具体的に誰で、何が分かれば「理解した」になるか
3. **ペルソナと物語** — ユースケースの物語の主人公は誰か。困りごと→解決はどう流れるか(シーンに割れる粒度まで)
4. **3幕の一文化** — 概要・物語・構成それぞれ「一文で言うと」何か
5. **削るもの** — 非エンジニアに見せない実装詳細はどれか

終了条件: 観点4の3文が確定するまで(目安2〜3ラウンド)。

### 3. 絵コンテ承認(唯一の関門)

次の表を提示する:

```markdown
| # | 幕 | 種別 | 画面の内容 | ナレーション | 尺目安 |
```

- 尺目安 = ナレーション文字数 ÷ 6 + 1 秒(四捨五入)
- 制約: 全体8〜12シーン / 物語シーン3〜5 / ナレーション合計700〜1,000字(=2〜3分) / **最終シーンはクレジット(削除禁止)**
- 表の下に必ず併記: **合計尺** / **コスト見積り**(物語シーン数 × 0.04ドル × 160円。TTS(Gemini 無料枠)・Remotion は ¥0 行として明示。※「$数字」表記はスキル引数置換に化けるため使用禁止) / **当月累計 → 見込み累計 / ¥3,000**
- **見込み累計 > ¥3,000 → 中断して報告**(承認を求めない)

分岐:
- **承認** → `WORKDIR` を作成し `storyboard.md` として保存 → 工程4
- **文言・表現レベルの修正指示** → 表を直して工程3内で再提示
- **前提への疑義・却下** → **工程2に戻る。映像生成には進まない**

### 4. ハイブリッド生成

1. 承認済み絵コンテを `WORKDIR/scenes.json` に機械的に変換する。スキーマは `RENDERER/src/types.ts`、実例は `RENDERER/fixtures/demo-scenes.json`。visual の肉付けは「画面の内容」の記述範囲内のみ(承認外の要素を足さない)
2. `node RENDERER/scripts/tts.mjs WORKDIR/scenes.json`(Gemini TTS で wav 生成+実測尺の書き戻し。無料枠のレート制限は自動リトライ)
3. `node RENDERER/scripts/genimage.mjs WORKDIR/scenes.json`(物語シーンの画像生成+cost.json 加算)
4. レンダー:

```bash
cd RENDERER && npx remotion render RepoTour \
  "WORKDIR/<repo名>-<日付>.mp4" \
  --props="WORKDIR/scenes.json" --public-dir="WORKDIR/assets"
```

- 失敗時は該当工程のみ再実行(両スクリプトとも生成済みスキップで二重課金・二重生成しない)
- ナレーションを直したシーンは該当 wav を削除して再実行。画像をやり直すシーンは該当 png を削除して再実行

**Imagen プロンプト規範:** 英語 / スタイル統一プレフィックス `soft flat illustration, muted colors, ` で始める / **画像内に文字を入れない**(`no text in image` を必ず付ける。文字情報は caption で載せる)

### 5. 出力と完了確認

1. `WORKDIR` に mp4 / storyboard.md / scenes.json / cost.json が揃っているか確認する
2. 台帳に1行追記し、当月累計を再計算する
3. ユーザーに提示: 動画パス + 実績コスト + **「本人確認: 事実誤りがないか視聴してください」**
4. 誤りの指摘 → 該当シーンのみ修正(wav/png 削除 → 再生成)→ 再レンダー
5. **事実誤りゼロの確認をもって完了**(完了の定義)

## ナレーション規範

- ですます調。1文50字以内。
- 専門語は平易な言い換えを先に置く(例: 「コードの置き場所であるリポジトリ」)
- 画面に表示する文字と同じ文をそのまま読み上げない。数字は丸める。
- 声はデフォルト「Kore」(Gemini TTS・落ち着いたトーン)。変える場合は scenes.json の `meta.tts.voiceName` / `stylePrompt` を調整する。クレジット表記(既定: 「音声・画像: Google Gemini」)は CreditsScene が `meta.tts.credit` から自動描画する。VOICEVOX 等クレジット必須のエンジンへ切り替える場合は `credit` の設定が義務。

## やりがちな失敗

| 失敗 | 正しくは |
|------|----------|
| 絵コンテ承認前に画像・音声を生成 | コスト発生は承認後のみ |
| 却下を工程3内の文言修正で済ませる | 前提への疑義は工程2に戻る |
| クレジットシーンを削る・尺を詰めるため省く | 生成AI利用の明示とエンジン規約遵守のため必ず最終シーンに置く |
| 見積り・当月累計を出さずに生成へ進む | 承認関門で必ず併記する |
| 自動読解の結果を確認せず絵コンテへ直行 | 誤読が本編に混入する。理解インタビュー必須 |
| 不明点ゼロの読解レポートを受理 | 「自信のない読解」最低1件を要求する |
| 画像に文字・ロゴを描かせる | 生成画像の文字は崩れる。文字は caption で載せる |
| エンジニア向けの実装詳細を盛り込む | 視聴者は非エンジニア。工程2の観点5で削る |

## Red flags — 手が止まったら

- 「このリポジトリは簡単だからインタビュー省略でいい」→ 省略しない。誤読は簡単なリポジトリでも起きる。
- 「画像を先に見せた方が承認を取りやすい」→ 却下されたら課金が無駄になる。絵コンテはテキストで承認。
- 「予算を少し超えるが誤差の範囲」→ 中断して報告。判断するのはユーザー。
- 「ナレーションと画面の文字が同じでも問題ない」→ 視聴者は二重に読まされる。どちらかに寄せる。
