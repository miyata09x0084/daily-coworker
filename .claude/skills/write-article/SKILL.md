# 記事作成

このskillは**オーケストレーター**として動作する。リサーチは `web-researcher`、レビューは `critic` に委任し、構成設計と執筆はメインClaudeが担当する。

## 入力の取り扱い

ユーザーの発話（例:「○○について記事を書いて」「ブログ書いて」）または、
command wrapper 経由で渡された引数から、記事のテーマを抽出する。テーマが
曖昧な場合は、対象読者・記事の目的・想定媒体を確認してから着手する。

## フェーズ1: 並列リサーチ（web-researcher × 3 並列起動）

`web-researcher` サブエージェントを **同時に3つ並列起動**する。テーマ共通、観点を変える:

| 並列起動 | 観点 | 役割イメージ |
|---|---|---|
| 調査 A | `latest` | テーマの最新情報・統計データ・最新動向 |
| 調査 B | `competitive` | 競合記事分析（Qiita / Zenn 等の既存記事、ギャップ） |
| 調査 C | `audience-needs` | 読者の疑問・SNS議論・検索キーワード傾向 |

各researcherは構造化サマリのみを返す。**生Webコンテンツはメインに入らない**。

## フェーズ2: 構成設計（メインClaude + ユーザー対話）

リサーチ結果を元に、メインClaudeが記事構成を設計する。

**設計項目:**
- ターゲット読者の定義
- 記事の差別化ポイント（既存記事との違い）
- 構成案（見出し・セクション構成）
- 各セクションで伝えるべき要点

**ユーザーへの確認:** 構成案をユーザーに提示し、承認を得る。修正要望があれば反映する。

## フェーズ3: 編集長レビュー（critic 起動）

`critic` サブエージェントを起動し、フェーズ2の構成案を渡す。

- 観点セット: `editor-in-chief`（読者価値 / 論理的な流れ / 差別化 / 実用性）
- レビュー対象: フェーズ2の構成案

**判定による分岐:**
- ✅ Go → フェーズ4へ
- 🔄 要修正 → 必須修正項目を踏まえてフェーズ2に戻り、構成を改修（**戻りは最大1回**）

## フェーズ4: 執筆（メインClaude）

承認された構成に基づいて、メインClaudeが記事を執筆する。

**執筆ガイドライン:**
- 段落は短く保つ（3-4文が目安）
- 箇条書き・テーブルを活用して読みやすくする
- コード例がある場合は実行可能なものを書く
- フェーズ1のリサーチ結果の根拠を自然に引用する
- 冒頭で読者の課題に共感し、最後に具体的な次のステップを示す

## フェーズ5: 最終レビュー（critic 起動）

`critic` サブエージェントを起動し、完成原稿を渡す。

- 観点セット: `final-review`（誤字脱字 / 事実確認 / コード確認 / SEO / 読者体験）
- レビュー対象: フェーズ4の完成原稿

**判定による分岐:**
- ✅ Go → 保存して完了
- 🔄 要修正 → 必須修正項目を反映してから保存（部分的な手直しのみ。大幅な構成変更が必要なら一段戻ってユーザーと相談）

**保存先:** `output/articles/YYYY-MM-DD-<テーマの英語slug>.md`

完成後、ユーザーに最終確認を求める。

## 設計ノート

- フェーズ1（リサーチ）と フェーズ3/5（レビュー）はサブエージェントに委任。Web生コンテンツや長い指摘ログがメインに入らない。
- フェーズ2（構成設計）と フェーズ4（執筆）はユーザーとの対話・最終成果物への責任が大きいため、メインClaudeが担当する。
- 各エージェントの責務・出力フォーマット・規約は `.claude/agents/<name>.md` に集約されており、このskillでは観点セットのみ指定する。
