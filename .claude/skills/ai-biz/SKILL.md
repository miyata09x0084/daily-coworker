# AI Biz — 生成AIの商機を発見し、門番が判定する

生成AIの新ツール・APIを「キャッチアップして終わり」にせず、**発見→発想→評価**のパイプラインで利益ライン（本業級=月数十万円以上）に届く事業機会かの判定まで運ぶ。

**核心原則:**

1. **これは「AIツールまとめ」ではない。** 機会候補に変換できないシグナルは載せない。「誰のどの支出を置き換えるか」に答えられない候補は候補ではない。
2. **門番は落とすのが仕事。** Kill には復活条件を必ず付ける（復活条件があるから安全に殺せる）。落とした候補も1行の記録を残す。
3. **見立ては台帳に記録し、期限到来で答え合わせする。** 事業眼は通算成績で鍛える。

**責務分担（設計判断）:** 技術で何が可能になったか（公式発表・論文・GitHub全般）は ai-leverage の領分。本スキルは生成AIプロダクト構築素材（マルチモーダル生成API・エージェントFW・観測ツール）と「何にお金が払われているか」だけを見る。両方を同じスキルで追うと二重取得と焦点ぼけを招くため分けた。

## 手順

### 0. 設定・台帳・答え合わせ

1. `.claude/skills/ai-biz/biz-sources.yaml` を Read する
2. `output/ai-biz/config.yaml`（個人設定・git管理外）を Read する。無ければ「週の可処分時間は？（既定10h）」を確認して作成する。以後この質問は繰り返さない
3. `output/ai-biz/ledger.md`（見立て台帳）を Read する。無ければ次の雛形で作成する:

```markdown
# AI Biz — 見立て台帳
（Go/Kill/Watch の見立てと答え合わせの記録。行は消さない）

| 記録日 | 対象 | 判定 | 復活条件/反証条件 | 期限 | 答え合わせ |
|--------|------|------|-------------------|------|------------|
```

4. **答え合わせ**: 台帳で期限到来の見立てを WebSearch で照合し、的中/外れ/学びを「答え合わせ」列に記録する。該当なしなら「期限到来の見立てなし」と出力に明記する

### 1. 入力モード判定

- **ツール指定**（「Sora 2でビジネスできる？」）→ 手順5へ直行
- **アイデア指定**（「AI議事録サービスってどう？」）→ 手順5へ直行
- **ノーヒント**（「何か儲かる機会ない？」「商機ある？」）→ 手順2から

### 2. 商機発見（fetch 並列）

biz-sources.yaml の sources を**並列で**取得する。

- 台帳・過去の出力と照合し、既出案件は再掲しない（差分のみ）
- `lookback_days`（既定7日）より古いシグナルは拾わない
- 取得失敗ルートはスキップしフッターに記録する（全体は止めない）。全滅なら水増しせず「本日は取得できず」と報告して終了する

### 3. 発想（3型）

シグナルを機会候補へ変換する。**使った型を候補に明記する**:

- **能力起点**: 何が安く/初めて可能になったか → 誰の高コスト業務が置き換わるか
- **市場起点**: 儲かっている既存サービスのAIネイティブ改善版（新規性は必須でない）
- **事例起点**: 他所・他分野で収益が出ている事例の輸入・横展開

### 4. 簡易足切り

候補を6軸でラフ判定（◎○△×）し、**生存上位 `max_candidates` 件（既定3）だけ残す**。

| 軸 | 問い |
|----|------|
| 切実度 | 誰かが今お金を払って解決している課題か |
| 市場規模 | 本業級（月数十万円）が成立する母数があるか |
| 競合と防御性 | 後発でも勝てる角度があるか |
| 実装コスト | 週`hours_per_week`時間×`mvp_deadline_months`ヶ月でMVP検証まで行けるか |
| モデル進化リスク | 次のモデル本体機能に飲み込まれるか（ラッパー淘汰） |
| 販路 | 最初の10人にどう届けるか（`01_strategy/luck-strategy.md` の発信活動と接続できるか。ファイルが無ければ一般論で判定） |

落とした候補は「足切りログ」に1行（候補名＋落とした軸＋理由1行）で残す。

### 5. 提示と指名 / 商機調査

- ノーヒント起動: 生存候補を提示し、**ユーザーが指名した候補だけ**深掘りに進む。指名が無ければ保存して終了する
- 深掘り対象が決まったら**商機調査**: WebSearch で競合サービス・価格帯・公開されている収益事例を集める。根拠タグを付ける（`実測` = 公開数字を直接確認 / `報道` = 記事経由 / `推定` = 自分の概算）

### 6. 機会評価（門番・壁打ち）

商機調査の材料で6軸を判定し、**Go / Kill / Watch** の3値で宣告する。

- **Go**: 「最初の一歩」（今週やる最小アクション）を1つだけ付ける
- **Kill**: **復活条件を必ず付ける**（何が変われば掘り返すか、具体的に）
- **Watch**: **反証条件と期限を必ず付ける**（期限なしの Watch は判定回避）

**規律（違反は即やり直し）:**

1. 実装コスト軸は足切り条件。週`hours_per_week`時間で`mvp_deadline_months`ヶ月以内にMVP検証不能なら、他が満点でも Go にしない
2. 市場規模は桁で判断する。桁の根拠（出典つき）が無ければ Watch に落とす
3. 判断が割れる軸は壁打ちとしてユーザーに問う。ただし門番として甘くしない——ユーザーの熱意は判定材料ではない

**Kill 宣告のトーン（本人指定・自分ごと型）:**
評論家の口調（「〜と思われます」「〜という見方もあります」）を使わず、一人の開発者として自分ごとで宣告する。
「私なら今の条件ではやりません。なぜなら{最も重い軸の根拠}」の形で、判断を自分として引き受ける。
復活条件も同じ一人称で添える:「{条件}が変わったら、私ならもう一度検討します」。

### 7. 保存と台帳更新

1. 発見レポート: `output/ai-biz/{YYYY-MM-DD}-discovery.md` / 評価: `output/ai-biz/{YYYY-MM-DD}-{対象slug}.md` に保存する
2. Go/Kill/Watch の判定を台帳に追記する（記録日・対象・判定・復活/反証条件・期限）

## 出力フォーマット（絵文字なし）

発見（ノーヒント起動）:

```markdown
# AI Biz 発見 — {YYYY-MM-DD}

## 答え合わせ（期限到来分）
- {対象}: 見立て{判定}（{記録日}） → 実際: {1行} → 学び: {1行}

## 機会候補（足切り生存 最大{max_candidates}件）
- **{候補名}**（{発想の型}｜出典: {source} {M/D}）
  - 何が新しく可能/安価になったか: {1行}
  - 誰のどの支出を置き換えるか: {1行}
  - 6軸ラフ: 切実度{◎○△×} 市場{} 競合{} 実装{} 淘汰{} 販路{}

## 足切りログ
- {候補名}: {軸}で落とした——{理由1行}

---
取得: {成功ルート} ｜ 失敗: {あれば名前、無ければ「なし」}
```

評価（門番）:

```markdown
# 機会評価 — {対象}（{YYYY-MM-DD}）

## 判定: {Go / Kill / Watch}
{判定の宣告。Kill のトーンは手順6の定義に従う}

## 6軸
| 軸 | 判定 | 根拠（出典・根拠タグつき） |

## {Go: 最初の一歩 / Kill: 復活条件 / Watch: 反証条件と期限}
```

## このスキルの正直な限界（仕様）

- 収益事例は**公開されたものしか拾えない**（生存バイアス。静かに稼ぐ事業は見えない）
- 市場規模は概算。数字の精度でなく桁で判断する
- X由来のローンチ情報は直接取得不可（ai-mentors と同じ三重封鎖）

## やりがちな失敗

| 失敗 | 正しくは |
|------|----------|
| 面白い技術をそのまま候補に載せる | 「誰のどの支出を置き換えるか」に答えられないなら候補にしない |
| せっかく調べたから Go にする | sunk cost は判定材料ではない。門番は落とすのが仕事 |
| 全部 Watch にする | 判定回避。復活条件があるから安全に Kill できる |
| 市場規模を「大きそう」で通す | 桁の根拠（出典）が無ければ Watch に落とす |
| 評価のたびに可処分時間を聞き直す | config.yaml に保存済み。初回のみ |

## Red flags — 手が止まったら

- 「この技術すごいから何かに使えるはず」→ 用途から逆算していない。発想の3型に戻る。
- 「競合がいないから勝てる」→ 競合ゼロは市場ゼロの兆候でもある。切実度の証拠を先に。
- 「ユーザーが乗り気だから Go に寄せたい」→ 熱意は判定材料ではない。軸の根拠だけで判定する。
- 期限のない Watch を書きそうになった → それは判定の先送り。期限を切るか Kill にする。
