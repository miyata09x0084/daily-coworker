# ディープリサーチ

このskillは**オーケストレーター**として動作する。実調査は `web-researcher` / `synthesizer` / `critic` の各サブエージェントに委任し、メインClaudeはフェーズ進行とユーザー対話に専念する。

## 入力の取り扱い

ユーザーの発話（例:「○○について調べて」）または、command wrapper 経由で
渡された引数から、調査テーマを抽出する。テーマが曖昧な場合は、調査範囲・
期間・観点を確認してから着手する。

## フェーズ1: 並列調査（web-researcher × 3 並列起動）

`web-researcher` サブエージェントを **同時に3つ並列起動**する。各起動でテーマは共通、観点だけを変える:

| 並列起動 | 観点 | 役割イメージ |
|---|---|---|
| Researcher A | `latest` | 直近1年の最新情報・公式リリース・統計を収集 |
| Researcher B | `background` | 技術的・歴史的背景、関連技術との比較を収集 |
| Researcher C | `critical` | 反対意見・課題・リスク・失敗事例を収集 |

各researcherは構造化サマリのみを返す（詳細は `.claude/agents/web-researcher.md` の出力フォーマット参照）。**生Webコンテンツはメインに入らない**。

## フェーズ2: 統合（synthesizer 起動）

`synthesizer` サブエージェントを起動し、フェーズ1の3出力を渡す。

- 統合ゴール: 「リサーチレポート骨子」
- 発見項目数の目安: 5-7
- 入力: Researcher A / B / C の出力

synthesizerは統合骨子 + 矛盾点リストを返す。

## フェーズ3: レビュー（critic 起動）

`critic` サブエージェントを起動し、synthesizerの出力を渡す。

- 観点セット: `research-review`（事実正確性 / 論理整合 / 網羅性）
- レビュー対象: フェーズ2の統合骨子

**判定による分岐:**
- ✅ Go → フェーズ4へ
- 🔄 要修正 → 必須修正項目を踏まえて、フェーズ1の不足観点で `web-researcher` を追加起動 → フェーズ2を再実行（**再実行は最大1回**）

## フェーズ4: レポート作成（メインClaude）

レビュー合格した統合骨子を元に、メインClaudeが最終レポートを以下のフォーマットで作成する:

```markdown
# リサーチレポート: <テーマ>
日付: YYYY-MM-DD

## エグゼクティブサマリー
<3-5行で結論>

## 主要な発見事項
1. ...
2. ...

## 詳細分析
### 最新動向
...
### 技術的背景
...
### リスクと課題
...

## 結論と推奨事項
...

## 参考文献
- [タイトル](URL) — 概要
```

**保存先:** `output/research/YYYY-MM-DD-<テーマの英語slug>.md`

## 設計ノート

- フェーズ1-3は**サブエージェントに委任**することで、Web検索の生レスポンスや長い引用がメインClaudeのコンテキストに入らない。各エージェントは構造化サマリのみ返す規約。
- フェーズ4の執筆はメインClaudeが担当（参考文献の整形・ユーザー対話への即応のため）。
- 各エージェントの責務・出力フォーマット・規約は `.claude/agents/<name>.md` に集約されており、このskillでは観点のみ指定する。
