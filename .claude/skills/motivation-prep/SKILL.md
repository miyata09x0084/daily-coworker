# 志望理由作成

## 概要

経歴書と募集要項の2ファイルから、志望理由を2形態で作る:
- **口頭メモ** — 面接「なぜ当社か」で語る、キーワード見出し＋話し言葉
- **提出文書** — 志望理由書・エントリーシートとして提出する完成文章（書き言葉・数百字）

両形態は同じ「重なり分析」から派生させ、事実が一致して矛盾しないようにする。

**核心原則: 志望理由は「募集要項 × 経歴書の事実」の重なりからだけ導く。盛らず、他社では言えない固有の重なりを、自分の言葉で。**

## 応答の方向性（5軸）

1. **重なりから導く（核心）** — 憧れ・なんとなく・知名度から作らない。募集要項の要件・人物像・事業・技術・フェーズ・固有の課題と、経歴書の事実が重なる点だけが志望理由になる。
2. **他社で言えない固有性** — 企業名を他社に差し替えても成立する理由は志望理由ではない。「成長したい」「技術が好き」「将来性を感じた」「バリューに共感」で終わらせず、その企業固有の要素に結びつける。行動指針・バリューとの「価値観が一致」も、それ単体では他社で言えるので固有要素と結ぶ。
3. **誠実性を最優先する** — 盛らない。経歴書の事実から離れない。盛った瞬間に矛盾が生まれる。志望度・熱意も誇張しない（「強く惹かれ」「ぜひとも」「心から」「共鳴」「確信しています」「強く志望」のような感情の盛りは事実ではない）。未経験・ギャップは隠さず、補い方とセットで述べる。
4. **普遍的価値で接続する** — 表層の技術スキルでなく、AIが進化しても人に残る普遍的な強み（未知の領域に構造を与えて学ぶ力／何を・なぜ作るかを決め設計する力／課題を定義し意思決定を前に進める力）で重なりを語る。技術はその表れとして添える。
5. **断定でなくメタ視点で、形態に応じた語り口で** — 「これが私の価値です」「確信しています」のような自己評価の断定を避ける。事実を述べ、控えめに意味づけする（事実 →「〜だと考えています」程度）。口頭メモは短文・話し言葉、提出文書は簡潔な書き言葉。形態で語り口を切り替える。

## 手順

### 1. 入力収集
経歴書と募集要項のファイルパス（または内容）をユーザーに尋ねる。
- 既定の置き場所: `output/applications/`（経歴書 `職務経歴書_*.md`、JD `*-jd.md`）
- **両方が揃うまで先に進まない。** 推測で経歴を補わない。

### 2. 重なり分析
- 募集要項を分解する: **必須要件 / 歓迎要件 / 求める人物像 ＋ 事業・技術・フェーズ・固有の課題**。
- 経歴書の事実とマッピングし、**重なり3点**を抽出する。
- 各重なりを「**他社で言えるかテスト**」にかける: 企業名を他社に差し替えて成立するなら固有性が弱い。固有の要素に結び直す。
- 各重なりを「軸4（普遍的価値）」で言い換える。
- ギャップ（未経験・不足）も洗い出し、正直な補い方を用意する。

### 3. 2形態を共通土台から生成
重なり3点を土台に、2つの形態を作る:
- (a) **口頭メモ**: 各重なりを **キーワード見出し**（太字、本番で一目で思い出せる）＋ 1〜2文の話し言葉ドラフト。
- (b) **提出文書**: 重なりを地の文にした数百字。構成は **導入 → 重なり3点 → 結び**。

数字・固有名は経歴書の事実のみ。定量データがない実績は「体感」と明示する。

### 4. 批判的レビュー（採用担当者視点）
ドラフトができたら、**保存前に必ず**、サブエージェントに批判的レビューを依頼する（メインのコンテキストを汚さず、別視点で読ませる）。

**サブエージェントへの依頼:**
- 役割を与える: 「あなたはこのポジションの採用担当者／面接官。この志望理由を通すか見極める、懐疑的な読み手として読む」
- 渡すもの: 志望理由ドラフト全文（口頭メモ＋提出文書）＋ 募集要項 ＋ 経歴書（事実確認用）
- 観点は**2点だけ**に絞る（盛り・書き言葉・敬語などの規則チェックはさせない。それは軸の役目で二重化しない）:
  - (i) **固有性**: 企業名を他社に差し替えても成立しないか。汎用的な「成長したい」「技術が好き」で終わっていないか。一番固有性が弱い箇所を1つ挙げさせる。
  - (ii) **誠実性**: 嘘くさい・盛っていないか。経歴書の事実から浮いている主張はないか。一番盛って見える箇所を1つ挙げさせる。
- 出力フォーマット: 〔どの箇所〕→〔固有性/誠実性のどちらが弱いか〕→〔採用担当者ならこう突く〕のリスト

**レビューを受けて、メイン側で修正版を作る:**
- 固有性が弱い箇所を、**経歴書の事実と募集要項の固有要素の範囲で**結び直す。
- 事実で強くできない弱点は、本体を盛らず、**追い質問への正直な備え**としてメモに足す。

> ⚠️ レビュアーは構造上「もっと熱意を盛れ／志望度を高く見せろ」という圧をかけてくる。**修正は必ず軸3（誠実性）・軸2（固有性）を上位に置く。** 盛って突っ込みを回避するのは禁止——突っ込みには正直な答えを用意する。事実で埋まらない弱点は「盛る」サインではなく「正直な備えを書く」サイン。

### 5. 出力
`output/applications/志望理由_{企業名}_{YYYYMMDD}.md` に保存する。1ファイルに2形態を同居させる。

## 出力テンプレート

```markdown
# 志望理由｜{企業名}（{YYYY-MM-DD}）

## 0. 志望理由の核（自分への約束）
- 募集要項×経歴書の重なりだけから導く。盛らない。
- 他社名に差し替えたら成立しない＝固有であること。
- 自己評価を断定しない。事実を述べ、控えめに意味づけ。
- 志望度・熱意を誇張しない。

## 1. 重なり分析（土台）
- **{重なり1}** — JD要件/固有要素「__」× 経歴書の事実「__」（普遍的価値: __）
- **{重なり2}** — 同上
- **{重なり3}** — 同上

## 2. 口頭メモ（面接「なぜ当社か」用・話し言葉）
- **{キーワード1}** — {1〜2文}
- **{キーワード2}** — {1〜2文}
- **{キーワード3}** — {1〜2文}

## 3. 提出文書（志望理由書・書き言葉・数百字）
{導入 → 重なり3点 → 結び の文章}

## 4. 突っ込まれたら（正直な備え）  ← 手順4のレビュー結果
- **{固有性/誠実性への追い質問}** — {盛らず事実ベースの返し}
```

## よくある失敗

| 失敗 | 直し方 |
|------|--------|
| 「成長したい」「技術が好き」で終わる | 他社で言えない固有の重なりに落とす（他社差し替えテスト） |
| 憧れ・知名度・なんとなくで語る | 募集要項×経歴書の事実の重なりから導く |
| バリュー・行動指針と「価値観が一致」で文化適合を語る | それも他社で言える。固有要素（事業・技術・課題）との重なりで語る |
| 「共鳴」「確信しています」で感情を盛る | 事実→控えめな意味づけ。感情語で強さを演出しない |
| 口頭メモが暗唱用の文章になる | キーワード見出し＋短い話し言葉。文書は section 3 に分離 |
| 提出文書を話し言葉で書く | 形態で語り口を切替。提出文書は簡潔な書き言葉 |
| 熱意・志望度を盛る（「強く惹かれ」等） | 経歴書の事実のみ。盛った瞬間に矛盾。データなしは「体感」 |
| 経歴書にない経験・肩書きを作る | 経歴書の事実から離れない |
| 自己評価を断定する | 事実を述べ、控えめに意味づけ |
| レビューをせず保存する | 保存前に採用担当者視点のサブエージェントレビューを必ず通す |
| レビュアーに規則チェックまでさせる | レビュアーは固有性・誠実性の2点だけ |
| 突っ込み回避のため盛って修正する | 軸3・軸2が最優先。事実で埋まらない弱点は「正直な備え」に変換 |
