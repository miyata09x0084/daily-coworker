# 出力文章の規範（Writing Style）

deep-research のレポート、write-article の記事など**出力系スキルが文章を
生成・レビューするとき**に適用する共通ルーブリック。実行時に該当フェーズが
Read して従う。常時ONではない（雑談や短い応答には適用しない）。

## 適用者

- **執筆担当**（deep-research Phase4 / write-article Phase4）: 執筆前に本ファイルを
  Read し、6原則すべてを満たす。
- **レビュー担当**（deep-research Phase4の自己検証 / write-article Phase5）: 末尾の
  チェックリストで合否判定。1つでも未達なら書き直す／差し戻す。

## 6原則（検証可能ルール）

| # | 原則 | ルール | 検証 |
|---|------|--------|------|
| ① | 結論ファースト（読み返し不要） | 各節は最初の1文で結論を述べ、根拠は後。見出しは可能なら"主張"にする（テンプレ既定の見出しは維持可） | 見出し＋各節冒頭文だけで骨子が通るか |
| ② | 専門語の即時橋渡し | 初出の専門語は「語（＝平易な言い換え／一言比喩）」で即注釈。暗黙の前提を置かない | 初出の専門語に注釈があるか |
| ③ | 3層速読設計 | 層1=30秒要約(TL;DR) / 層2=太字＋主張見出しで3分 / 層3=本文 | 上位2層だけで意思決定できるか |
| ④ | 専門性の担保 | 正確な用語を薄めない。噛み砕きは②の足場で行い語自体は残す。専門性は"正しい語＋一次情報"でにじませる | 正確な用語が保持され、かつ②があるか |
| ⑤ | 論理の連結 | 主張→根拠→含意の順。接続を明示（だから／一方で／つまり）。飛躍を作らない | 隣接する主張が接続語で辿れるか |
| ⑥ | 再現性の暗示 | 導出方法を残す（どのソースからどう導いたか）。出典URL・信頼度・日付を付す。**出典は主張と正しく対応させる**（数値・事実の引用元を取り違えない） | 主要な主張に出典・導出が紐づき、かつ出典が主張と正しく対応しているか |

## ②×④の両立（設計の核）

専門語は**消さず**、初出で**必ず橋渡す**。

- ❌ 「KVキャッシュを最適化した」（不親切）／「AIを速くした」（専門性ゼロ）
- ✅ 「LLMのKVキャッシュ（＝生成中に過去トークンの計算結果を保持する仕組み）を
  最適化し、長文応答のレイテンシを下げた」

専門性は"正しい語の選択"と"一次情報の参照"でにじませる。誇張しない。

## レビュー用チェックリスト（全✅で合格 / 1つでも未達→書き直し・差し戻し）

- [ ] 見出し＋各節冒頭文だけで骨子が通る（①）
- [ ] 初出の専門語に注釈がある（②④）
- [ ] 冒頭要約だけで結論が分かる（③）
- [ ] 正確な用語が薄められていない（④）
- [ ] 主張間が接続語で連結され飛躍がない（⑤）
- [ ] 主要な主張に出典・導出が紐づき、出典が主張と正しく対応している（数値・引用元の取り違えがない）（⑥）
