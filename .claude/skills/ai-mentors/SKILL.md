# AI Mentors — 一流の思考と振る舞いを自分に写像する

AI業界の第一人者の発信を「読んで終わり」にせず、**観察→写像**（思考・意思決定・振る舞いの型 → 自分の行動の変更）へ変換する。

**核心原則:**

1. **これは「Xまとめ」ではない。** 「何を言ったか」で終わる項目は載せない。人物に現れる**型**を観察し、自分の行動に写像する。
2. **デイリーの価値は差分にある。** 既読台帳と照合し、掲載済みの発信は再掲しない。新規ゼロの日は正直にゼロと書く。
3. **日付の裏が取れない発信は載せない。** 鮮度の偽装（古い発信の「直近」提示）は水増しと同罪。

## 手順

### 0. 設定と既読台帳

1. `.claude/skills/ai-mentors/mentors.yaml` を Read する
2. `output/ai-mentors/seen.md`（既読台帳）を Read する。無ければ次の雛形で作成し、`lookback_days` 遡って初回実行する:

```markdown
# AI Mentors — 既読台帳
（掲載済み発信の記録。差分抽出に使う。行は消さない）

| 掲載日 | 人物 | 発信日 | 発信の一言要約 | URL/ID |
|--------|------|--------|----------------|--------|
```

### 1. fetch（ルート並列）

mentors.yaml の `routes` を **並列で** 取得する:

- `rss`: WebFetch で RSS/Atom を取得し、監視対象人物への言及を抽出
- `web-search`: WebSearch で人物ごとに直近の重要発言を報道経由で検知
- `webpage-extract`: WebFetch でページを取得（補助扱い。単独ソースにしない）

**日付規律（違反は即やり直し）:**

1. 各シグナルに**裏取り済みの絶対日付**を付ける。裏取り手段: 報道記事の発行日／RSS pubDate／X status ID の Snowflake 逆算（`(id >> 22) + 1288834974657` = ms epoch）
2. スクレイパーの相対表示（「2時間前」）を日付として採用禁止——31日前の投稿を「2時間前」と表示する実例がある
3. 日付が裏取りできない発信は載せない

- 取得に失敗したルートはスキップし、フッター用に記録する（全体は止めない）
- 全ルート失敗なら、捏造・水増しせず「本日は取得できず」と正直に報告して終了する

### 2. 差分抽出

- 既読台帳と照合し、**掲載済みの発信は除外**する（照合は件数でなくURL/IDと要約の同一性で）
- `lookback_days`（既定7日）より古い発信は初回でも拾わない
- 人物ごとの新規件数を記録する。ゼロはゼロのまま——**8人分の体裁を整えるための水増し禁止**

### 3. 観察 → 写像【中核：ここが全価値】

新規シグナルごとに3点セットで書く。**3点目が書けないシグナルは載せない**:

1. **事実**: 発信内容1行（発信日付・出典つき）
2. **観察**: そこに現れる思考・意思決定・振る舞いの**型**（内容の要約ではない。mentors.yaml の `focus` が観察の当たりをつける補助線）
3. **写像**: 自分の今日の行動・判断を具体的にどう変えるか

**規律（違反は即やり直し）:**

1. 「〜と発言した」で終わる項目は禁止。観察と写像が付かないなら切る
2. **全体で最大5件**。多い日は写像の強さで削る。全員分載せる義務はない
3. **根拠タグ必須**（3段階、迷ったら弱い方に倒す）:
   - `原文` — 一次テキスト（本人ブログ・公式文書・アーカイブ）を直接確認した
   - `報道` — メディア記事の引用経由
   - `又聞き` — 検索スニペット・要約・SNS転載経由
4. **逐語引用（かぎ括弧・引用符）は `原文` のみ。** `報道`/`又聞き` は要旨として書く。x.com の status URL は取得不可(402)——開けないURLを検証済みソースのように提示しない
5. **写像は最後に1つへ絞る**（今日の一手）。アクションを並べるほど実行率は下がる

### 4. 出力フォーマット（絵文字なし）

```markdown
# AI Mentors — {YYYY-MM-DD}

## 今日の観察（新規のみ・最大5件）
- **{人物}**（{発信日 M/D}）: {事実1行} ｜根拠: {原文/報道/又聞き} [{source}]
  - 観察: {思考・意思決定・振る舞いの型}
  - 写像: {自分の行動・判断の変更}

## 今日の一手
{写像から1つ、今日実行する最小アクション}

---
検知状況: {8名全員を「{名前} 新規{n}」「{名前} なし」「{名前} 取得失敗」のいずれかで列挙。省略禁止}
取得: {成功ルート名} ｜ 失敗: {あれば名前、無ければ「なし」}
```

- 新規ゼロの日は「## 今日の観察」の下に「本日、新規の注目発信なし」と書く（過去分の再掲で埋めない）
- 絵文字は使わない

### 5. 保存と台帳更新

1. `output/ai-mentors/{YYYY-MM-DD}-ai-mentors.md` に保存する
2. 掲載した発信を既読台帳に追記する（掲載日・人物・発信日・一言要約・URL/ID）

## このスキルの正直な限界（仕様）

取れるのは「注目を集めた発言」を0〜2日遅れで、まで。バズらなかった小さな投稿は拾えない（API課金なしでは Nitter全滅・x.com 402・検索索引2〜7週遅延の三重封鎖）。**この限界を水増しで隠さない**——検知状況フッターがその担保。

## やりがちな失敗（ベースライン観察済み）

| 失敗 | 正しくは |
|------|----------|
| デイリーと言いつつ「直近1ヶ月ダイジェスト」を毎回出す | 既読台帳との差分のみ。翌日また同じ話を「直近」として再掲しない |
| 項目の日付が人物によって有ったり無かったり | 全項目に裏取り済み絶対日付。裏取り不能なら載せない |
| x.com の status URL を検証済みソースのように列挙 | 開けないURL。スニペット由来は `又聞き` タグ＋要旨化 |
| 8人分のセクションを古い発信で充填 | 人物別セクションは作らない。新規だけ載せ、検知状況フッターで透明化 |
| アクション10連発で薄まる | 観察は最大5件・今日の一手は1つ |

## Red flags — 手が止まったら

- 「先月の発信だけど良い内容だから載せたい」→ 台帳を確認。掲載済みなら再掲禁止。未掲載でも lookback より古ければ載せない。
- 「この人の欄が空だと格好つかない」→ 空は正直に。「なし」はこのスキルの誠実さの証明。
- 「名言っぽく引用符で書きたい」→ 原文を直接確認したか？ してないなら要旨に直す。
- 「日付は書いてあったから大丈夫」→ それは誰が付けた日付か。スクレイパー表示なら裏取りする。
- 出力が長い → 写像が弱い項目が混ざっている。5件まで削る。

## 人物・ルート追加

`mentors.yaml` に entry を1つ足す。既存 `fetch.strategy` に該当すれば本体修正は不要。新パターンなら手順1にブロックを追記する。
