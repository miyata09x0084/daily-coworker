# AI Leverage — 一次情報を判断力に変える

AIの一次情報を「読んで終わり」にせず、SWE視点の **インサイト→アクション** へ変換する。

**核心原則:**

1. **判断・行動を1つも変えない情報は、どれだけ話題でも載せない。**
2. **検証されない見立ては、判断力を鍛えない。** 見立てには反証条件と期限を付け、後日必ず答え合わせする。

これは要約スキルではない。"今日何が起きたか" ではなく "だからお前は何を変えるか"、そして "前回の見立ては当たっていたか" を出す。

## 手順

### 0. 設定読み込み

1. `.claude/skills/ai-leverage/ai-sources.yaml` を Read する
2. `output/ai-leverage/ledger.md`（見立て台帳）を Read する。無ければ次の雛形で作成する:

```markdown
# AI Leverage — 見立て台帳

- ID = {起点日YYYY-MM-DD}-{当日連番}。判定済みの行も消さない（的中/外れの通算履歴が判断力の学習データ）。
- 判定済みが50行を超えたら `ledger-archive.md` へ移す（未決は残す）。

| ID | 見立て | 検証条件（観測可能な事象） | 期限 | 判定 | 学び |
|----|--------|--------------------------|------|------|------|
```

3. `${VAR}` 表記があれば `.env` を Read して展開する（現状は公開URLのみで `.env` 不要）

### 1. fetch（ソース並列）

`sources` 各 entry について **並列で** エージェントを起動し、生シグナルを取得する。
`fetch.strategy` で取得方式を切替える（未知の戦略が出たら、この手順にブロックを追記する）:

- `webpage-extract`: WebFetch で index ページを取得し、最近の投稿の title/url を抽出（RSSの無い公式ブログ向け）。bot保護で403になる公式サイト（例: openai.com）は、毎日失敗させず `github-releases` 等の到達可能な一次情報に切替える
- `rss`: WebFetch で RSS/Atom を取得し、先頭 `limit` 件の title/url/published を抽出
- `arxiv-api`: WebFetch で arXiv API（`fetch.url`）を叩き、Atom entry から title/url/summary を抽出
- `hf-papers`: HF MCP `paper_search`（無ければ WebFetch `huggingface.co/papers`）で当日の論文を取得。レート制限時は `fetch.fallback`（=arxiv-api）に切替
- `github-trending`: WebFetch で `fetch.url` を取得し、AI/LLM/agent 関連のリポジトリだけ抽出
- `github-releases`: `fetch.repos` 各 repo の最新リリースを WebFetch（api.github.com）で取得

**返却（共通）**: `title / url / source(=entry の name) / tier / abstract(任意)`

- 取得に失敗したソースは **スキップ** し、フッター用に「失敗: <name>」を記録する（全体は止めない）
- 全ソース取得後、URL重複・タイトル酷似を除去する
- 全ソースが失敗したら、捏造・水増しせず「本日は一次情報を取得できず」と正直に報告して終了する

### 2. 答え合わせ（台帳照合）【判断力を複利にする装置】

台帳の「未決」の見立てを1件ずつ、当日のシグナルと今日の日付に照合して判定する:

- **的中** — 検証条件が観測された
- **外れ** — 期限を過ぎたのに検証条件が観測されていない。**「なぜ外れたか」一言必須**
- **未決** — 期限内でまだ条件未観測。そのまま残す

**規律（違反は即やり直し）:**

1. **期限超過＝外れ。** 「時期尚早」への言い換え・期限の無言延長・外れの不掲載は**最重度の違反**。外れを隠した答え合わせは、答え合わせをしないより悪い（当たった記憶だけが残り、判断が過信に歪む）。外れは学びの原料であり、このセクションの存在理由。
2. 判定した行は台帳の 判定・学び 列を埋めて確定する。**行は消さない**（通算履歴が資産）。
3. 判定は願望ではなくシグナルで裏を取る。「当たっているはず」は判定ではない。

### 3. 合成 → アクション【中核：ここが全価値】

入力 = 生シグナル配列。出力 = 3レンズ別の「インサイト→アクション」。
**ここで要約に堕ちると、このスキルは無価値になる。** 以下の規律を必ず守る。

**レンズ（＝出力3セクション＝時間軸）:**
- **Now〔生産性〕** — 今日〜今週、手を動かして取り入れる改善
- **Watch〔キャリア・市場価値〕** — SWEという職種・自分の市場価値が中期でどう変わるか
- **メタトレンド〔判断力〕** — 複数シグナルを横断した構造変化と、思考の更新

**規律（違反は即やり直し）:**

1. **「切る」＝削除。再分類ではない。** 判断を変えないシグナルは出力から **消す**。「スルー可」「知っておく」「ノイズ」のような “全部載せて札を貼る” セクションを作ってはいけない。消したシグナルは、フッターの「切り捨て」行に **件数＋一言理由だけ** を書く（本文に再掲しない）。
2. **キャリアレンズを必ず一度は問う。** 放っておくと目の前の実装/生産性に偏り、Watch が空になる（ベースラインで両者とも欠落した既知の失敗）。各シグナルに「これは SWE の市場価値・職種の変化に何を意味するか」を必ず一度当てる。本当に無ければ「今日はキャリアで動かす項目なし」と正直に書く。
3. **各項目は「シグナル → アクション/含意」。** 事実だけの項目は禁止。アクション or 動くトリガーが書けないシグナルは、切り捨て対象。
4. **メタトレンドは複数シグナル横断。** 1件だけの話はトレンドではなく要約。横断できなければメタトレンドは0件でよい（無理に作らない）。
5. **空レンズは正直に空と書く。水増し禁止。**
6. **各レンズ目安3・最大5。** 出力が長くなったら、それは切れていない兆候。まず actionability で削り、なお多ければ重要度で上位だけ残す。
7. **全シグナルを台帳で disposition する（透明性の担保）。** 出力を書く前に、取得した全シグナルを**1件ずつ番号で列挙し**、各々に「掲載（どのレンズか）」か「切り捨て（一言理由）」を必ず割り当てる。どちらにも入らないシグナルが1件でもあれば未処理＝やり直し。**件数の辻褄合わせは禁止**（本文数を水増しして等式を合わせるのは違反）。照合は件数ではなく**シグナルの同一性**で行い、取りこぼしゼロを名前で確認する。境界事例（人気/スター達成など capability 変化のないもの）こそ落としやすい——迷ったら切り捨て側に明示で入れる。切り捨ては必ずフッターに理由ごと列挙し、その数と「切り捨て {N}件」の N を一致させる。**シグナルを無言で消さない。** 切り捨てが多い日（目安15件超で個別名指しがフッターを肥大化させるとき）は、切り捨てを**カテゴリ別バケット**に束ね、各バケットに件数＋一言理由を付ける——バケット件数の合計を N に一致させれば員数照合は保たれる（例:「論文9（ドメイン特化で実務判断を変えず）／軽微リリース6 …」）。件数が少なければ個別名指しのままでよい。
8. **掲載する Now・Watch の各シグナルに根拠強度をタグ付けする。** 3段階:
   - `実測` — 再現手順・第三者ベンチマークがある
   - `実装済` — 出荷済みで今日試せるが、性能主張は未検証
   - `主張のみ` — 発表・デモ・論文の自己申告段階
   **迷ったら弱い方に倒す**——強度の水増しは切り捨ての水増しと同罪。デモ動画と自社ベンチは `実測` ではない。
9. **Watch・メタトレンドの各項目に反証条件を必須で付ける。** 「外れる条件: 〜」を**観測可能な事象＋期限**で書く（「流行らなければ」は不可。「3ヶ月以内に主要プロバイダの採用発表が無ければ」は可）。**反証条件が書けない見立ては載せない**——書けない＝自分が何を信じているか分かっていないサイン。

### 4. 出力フォーマット（絵文字なし）

```markdown
# AI Leverage — {YYYY-MM-DD}

## 答え合わせ — 前回までの見立て
- 的中: {見立て}（{起点日}） — {観測された事象} → 学び: {一言}
- 外れ: {見立て}（{起点日}） — なぜ: {一言} → 学び: {一言}
- 未決 {n}件（台帳参照）

## Now — 今日動かす〔生産性〕
- {シグナル1行} → やること: {具体アクション/試す実験} ｜根拠: {実測/実装済/主張のみ} [{source}]

## Watch — 判断を更新する〔キャリア・市場価値〕
- {シグナル} → 含意: {市場価値への意味} ／ 動くトリガー: {何が起きたら動くか} ／ 外れる条件: {観測可能な反証条件＋期限} ｜根拠: {実測/実装済/主張のみ} [{source}]

## メタトレンド — 考え方をアップデート〔判断力〕
1. {複数シグナルを束ねた構造変化} → 思考の更新: {mental model / 判断軸} ／ 外れる条件: {観測可能な反証条件＋期限} [{src},{src}]

---
切り捨て {N}件（判断を変えないため不掲載）: {一言で何を捨てたか}
取得: official {n} / papers {n} / tools {n} ｜ 失敗: {あれば名前、無ければ「なし」}
台帳: 新規 {n} ／ 的中 {n} ／ 外れ {n} ／ 未決 {n}
```

- 該当ゼロのレンズは、見出しの下に「今日は〔X〕で動かす項目なし」と書く
- 判定対象が無い日の答え合わせは「本日判定なし（未決 {n}件）」と書く
- 絵文字は使わない

### 5. 保存と台帳更新

1. `output/ai-leverage/{YYYY-MM-DD}-ai-leverage.md` に保存する
2. 台帳を更新する:
   - 本日判定した行の 判定・学び 列を確定する
   - **Watch とメタトレンドの各項目を新規登録する**（Now は今日試す＝即検証なので登録不要）。見立て・検証条件・期限は出力の「外れる条件」と一致させ、判定は「未決」で登録する
   - 期限は検証条件が現実的に観測されうる最短で設定する。目安: Watch 1〜3ヶ月、メタトレンド 3〜6ヶ月。**「未定」は禁止**——期限が書けないのは検証条件が観測可能になっていないサイン

## やりがちな失敗（ベースライン観察済み）

| 失敗 | 正しくは |
|------|----------|
| 全件を「スルー可/知っておく/ノイズ」に振り分けて全部表示 | 判断を変えない物は **消す**。残すのは件数＋理由の1行だけ |
| Now（生産性）と実装の話ばかりで Watch（キャリア）が空 | 各シグナルにキャリアレンズを必ず一度当てる。無ければ正直に空と書く |
| 「〜がリリースされました」で終わる事実列挙 | 必ず「→ やること/含意/トリガー」を付ける。付かないなら切る |
| 網羅したくて長くなる | 長い＝切れていない。各レンズ最大5、量より質 |
| 絵文字・緊急度別やソース別の独自構造で出す | 3レンズ（Now/Watch/メタトレンド）固定。絵文字なし |
| デモ動画・自社ベンチの数字を `実測` とタグ付け | 再現手順・第三者ベンチが無ければ `主張のみ`。迷ったら弱い方 |
| 「いずれ主流になる」など反証不能な見立てを載せる | 観測可能な条件＋期限に落とす。落とせないなら載せない |
| 外れた見立てを「時期尚早」と言い換えて未決のまま延命 | 期限超過＝外れ。なぜ外れたかと学びを書く |

## Red flags — 手が止まったら

- 「一応載せておくか」→ それは切り捨て対象。消す。
- 「ノイズ専用セクションに入れよう」→ 再分類は禁止。件数だけフッターへ。
- 「キャリアに繋がる話が無い」→ 本当に？ 一度問うてから。無ければ空と明記。
- 出力が画面を超えて長い → 切れていない。actionability で削り直す。
- 「この数字はすごいから実測でいいだろう」→ 再現手順は？ 第三者ベンチは？ 無ければ `主張のみ`。
- 「反証条件が思いつかない」→ その見立ては載せない。
- 「外れというより時期尚早」→ 期限を過ぎたら外れ。学びを書いて、必要なら**新しい見立てとして**立て直す。
- 期限欄に「未定」と書きたくなった → 検証条件が観測可能になっていない。書き直す。
