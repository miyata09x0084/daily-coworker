# AI Leverage — 一次情報を行動に変える

AIの一次情報を「読んで終わり」にせず、SWE視点の **インサイト→アクション** へ変換する。

**核心原則: 判断・行動を1つも変えない情報は、どれだけ話題でも載せない。**

これは要約スキルではない。"今日何が起きたか" ではなく "だからお前は何を変えるか" を出す。

## 手順

### 0. 設定読み込み
1. `.claude/skills/ai-leverage/ai-sources.yaml` を Read する
2. `${VAR}` 表記があれば `.env` を Read して展開する（現状は公開URLのみで `.env` 不要）

### 1. fetch（ソース並列）

`sources` 各 entry について **並列で** エージェントを起動し、生シグナルを取得する。
`fetch.strategy` で取得方式を切替える（未知の戦略が出たら、この手順にブロックを追記する）:

- `webpage-extract`: WebFetch で index ページを取得し、最近の投稿の title/url を抽出（RSSの無い公式ブログ向け）。bot保護で403になる公式サイト（例: openai.com）は、毎日失敗させず `github-releases` 等の到達可能な一次情報に切替える
- `rss`: WebFetch で RSS/Atom を取得し、先頭 `limit` 件の title/url/published を抽出
- `arxiv-api`: WebFetch で arXiv API（`fetch.url`）を叩き、Atom entry から title/url/summary を抽出
- `hf-papers`: HF MCP `paper_search`（無ければ WebFetch `huggingface.co/papers`）で当日の論文を取得。レート制限時は `fetch.fallback`（=arxiv-api）に切替
- `github-trending`: WebFetch で `fetch.url` を取得し、AI/LLM/agent 関連のリポジトリだけ抽出
- `github-releases`: `fetch.repos` 各 repo の最新リリースを WebFetch（api.github.com）で取得

**返却（共通）**: `title / url / source(=entry の name) / tier / abstract(任意)`

- 取得に失敗したソースは **スキップ** し、フッター用に「失敗: <name>」を記録する（全体は止めない）
- 全ソース取得後、URL重複・タイトル酷似を除去する
- 全ソースが失敗したら、捏造・水増しせず「本日は一次情報を取得できず」と正直に報告して終了する

### 2. 合成 → アクション【中核：ここが全価値】

入力 = 生シグナル配列。出力 = 3レンズ別の「インサイト→アクション」。
**ここで要約に堕ちると、このスキルは無価値になる。** 以下の規律を必ず守る。

**レンズ（＝出力3セクション＝時間軸）:**
- **Now〔生産性〕** — 今日〜今週、手を動かして取り入れる改善
- **Watch〔キャリア・市場価値〕** — SWEという職種・自分の市場価値が中期でどう変わるか
- **メタトレンド〔判断力〕** — 複数シグナルを横断した構造変化と、思考の更新

**規律（違反は即やり直し）:**

1. **「切る」＝削除。再分類ではない。** 判断を変えないシグナルは出力から **消す**。「スルー可」「知っておく」「ノイズ」のような “全部載せて札を貼る” セクションを作ってはいけない。消したシグナルは、フッターの「切り捨て」行に **件数＋一言理由だけ** を書く（本文に再掲しない）。
2. **キャリアレンズを必ず一度は問う。** 放っておくと目の前の実装/生産性に偏り、Watch が空になる（ベースラインで両者とも欠落した既知の失敗）。各シグナルに「これは SWE の市場価値・職種の変化に何を意味するか」を必ず一度当てる。本当に無ければ「今日はキャリアで動かす項目なし」と正直に書く。
3. **各項目は「シグナル → アクション/含意」。** 事実だけの項目は禁止。アクション or 動くトリガーが書けないシグナルは、切り捨て対象。
4. **メタトレンドは複数シグナル横断。** 1件だけの話はトレンドではなく要約。横断できなければメタトレンドは0件でよい（無理に作らない）。
5. **空レンズは正直に空と書く。水増し禁止。**
6. **各レンズ目安3・最大5。** 出力が長くなったら、それは切れていない兆候。まず actionability で削り、なお多ければ重要度で上位だけ残す。
7. **全シグナルを台帳で disposition する（透明性の担保）。** 出力を書く前に、取得した全シグナルを**1件ずつ番号で列挙し**、各々に「掲載（どのレンズか）」か「切り捨て（一言理由）」を必ず割り当てる。どちらにも入らないシグナルが1件でもあれば未処理＝やり直し。**件数の辻褄合わせは禁止**（本文数を水増しして等式を合わせるのは違反）。照合は件数ではなく**シグナルの同一性**で行い、取りこぼしゼロを名前で確認する。境界事例（人気/スター達成など capability 変化のないもの）こそ落としやすい——迷ったら切り捨て側に明示で入れる。切り捨ては必ずフッターに理由ごと列挙し、その数と「切り捨て {N}件」の N を一致させる。**シグナルを無言で消さない。**

### 3. 出力フォーマット（絵文字なし）

```markdown
# AI Leverage — {YYYY-MM-DD}

## Now — 今日動かす〔生産性〕
- {シグナル1行} → やること: {具体アクション/試す実験} [{source}]

## Watch — 判断を更新する〔キャリア・市場価値〕
- {シグナル} → 含意: {市場価値への意味} ／ 動くトリガー: {何が起きたら動くか} [{source}]

## メタトレンド — 考え方をアップデート〔判断力〕
1. {複数シグナルを束ねた構造変化} → 思考の更新: {mental model / 判断軸} [{src},{src}]

---
切り捨て {N}件（判断を変えないため不掲載）: {一言で何を捨てたか}
取得: official {n} / papers {n} / tools {n} ｜ 失敗: {あれば名前、無ければ「なし」}
```

- 該当ゼロのレンズは、見出しの下に「今日は〔X〕で動かす項目なし」と書く
- 絵文字は使わない

### 4. 保存
`output/ai-leverage/{YYYY-MM-DD}-ai-leverage.md` に保存する。

## やりがちな失敗（ベースライン観察済み）

| 失敗 | 正しくは |
|------|----------|
| 全件を「スルー可/知っておく/ノイズ」に振り分けて全部表示 | 判断を変えない物は **消す**。残すのは件数＋理由の1行だけ |
| Now（生産性）と実装の話ばかりで Watch（キャリア）が空 | 各シグナルにキャリアレンズを必ず一度当てる。無ければ正直に空と書く |
| 「〜がリリースされました」で終わる事実列挙 | 必ず「→ やること/含意/トリガー」を付ける。付かないなら切る |
| 網羅したくて長くなる | 長い＝切れていない。各レンズ最大5、量より質 |
| 絵文字・緊急度別やソース別の独自構造で出す | 3レンズ（Now/Watch/メタトレンド）固定。絵文字なし |

## Red flags — 手が止まったら

- 「一応載せておくか」→ それは切り捨て対象。消す。
- 「ノイズ専用セクションに入れよう」→ 再分類は禁止。件数だけフッターへ。
- 「キャリアに繋がる話が無い」→ 本当に？ 一度問うてから。無ければ空と明記。
- 出力が画面を超えて長い → 切れていない。actionability で削り直す。

## ソース追加
`ai-sources.yaml` の `sources` に entry を1つ足す。既存 `fetch.strategy` に該当すれば本体修正は不要。新パターンなら手順1に戦略ブロックを追記する。
