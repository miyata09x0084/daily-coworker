# 面接準備メモ作成

## 概要

経歴書と募集要項の2ファイルから、面接の質疑応答メモをMarkdownで作る。
本番で一目見返せるスキャナブルな形式（キーワード見出し＋短い語り口）で出力する。

**核心原則: 盛らず、企業ニーズと自分の強みの重なりを、自分の言葉で示す。**

## 応答の方向性（全回答に貫く軸）

1. **普遍的な価値を示す（AI時代でも通用する）** — 言語・フレームワークなど表層の技術スキルは陳腐化しうる。その下にある、AIが進化しても人に残る普遍的な強みを軸に語る: 未知の領域に構造を与えて学び取る力／何を・なぜ作るかを決め、人に伝わる形に設計する力／課題を定義し意思決定を前に進める力。技術スキルはその表れの一つとして添える。
2. **ポテンシャルは事実で裏づける** — 将来性は願望でなく実績で示す。領域や技術を越えて適応してきた事実を挙げ、「だからこの先の変化にも適応できる」と控えめに接続する。誇張しない。
3. **重なりを言語化する** — 募集要項の要件・人物像 と 経歴書の事実 が重なる点を明示する。志望動機もこの重なりから導く。
4. **誠実性を最優先する** — 盛らない。経歴書の事実から離れない。盛った瞬間に矛盾が生まれる。未経験・ギャップは隠さず、補い方とセットで述べる。
5. **断定でなく、事実とメタ視点で語る** — 「これが私の価値です」「得意です」のような自己評価の断定を避ける。確かな事実を述べ、そこから一段上の視点で控えめに意味づけする（事実 → 「〜だと考えています」程度）。表面的な意気込みでなく、なぜそう言えるのかを事実で支える。すべての回答が同じ事実群から一貫して導かれ、互いに矛盾しないこと。
6. **歯切れ良く、ただし盛らない** — 短文・話し言葉・自分の言葉。「であります」「と考えております」等の過剰敬語と冗長な接続詞は間引く。歯切れの良さは文の形の話であり、自己評価を強く言い切ることではない（軸5と両立させる。過剰なヘッジで濁すのも避ける）。
7. **1問＝最大3テーマ** — 詰め込まない。本番で思い出せる量に絞る。トークを絞るセクション（自己紹介・志望動機・強み・技術深掘り・キャリア観）に効かせる。**例外**: 弱み・ギャップは数合わせで隠さず該当するものを正直に全部出す。逆質問は「事業／技術／チーム／役割」の4カテゴリで出す。

## 手順

### 1. 入力収集

経歴書と募集要項のファイルパス（または内容）をユーザーに尋ねる。

- 既定の置き場所: `output/applications/`（経歴書 `職務経歴書_*.md`、JD `*-jd.md`）
- **両方が揃うまで先に進まない。** 推測で経歴を補わない。

### 2. 重なり分析

- 募集要項を分解する: **必須要件 / 歓迎要件 / 求める人物像**。
- 経歴書の事実とマッピングし、**重なる強み3点**を抽出する。
- 各強みを「軸1（本質的価値）」で言い換える。
- ギャップ（未経験・不足）も洗い出し、正直な補い方を用意する。

### 3. 質問生成

標準カテゴリ＋募集要項由来の深掘りを自動生成する:

- 自己紹介（30秒）
- 志望動機（なぜ当社か）
- 強み / 弱み・ギャップ
- 技術深掘り（募集要項の必須・歓迎技術から逆算）
- キャリア観・働き方
- 逆質問（事業 / 技術 / チーム / 役割 のカテゴリ別）

### 4. 回答作成

各質問に対し、**最大3テーマ**。各テーマは:

- **キーワード見出し**（太字、本番で一目で思い出せる）
- ＋ 1〜2文の話し言葉ドラフト（自分の言葉、盛らない）

数字・固有名は経歴書の事実のみ。定量データがない実績は「体感」と明示する。

### 5. 批判的レビュー（面接官視点）

ドラフトができたら、**保存前に必ず**、面接官になりきったサブエージェントに批判的レビューを依頼する（メインのコンテキストを汚さず、別視点で読ませる）。

**サブエージェントへの依頼:**
- 役割を与える: 「あなたはこのポジションの採用面接官。通すかどうかを見極める、懐疑的で鋭い面接官として読む」
- 渡すもの: 質疑応答メモ全文 ＋ 募集要項 ＋ 経歴書（事実確認用）
- 観点は**面接官視点だけ**。盛り・書き言葉・敬語などの規則チェックはさせない（それは方針セクションの役目で、二重化しない）:
  - 各回答に「面接官ならどこを突くか」= 追い質問・反論を出させる（例:「それ具体的にどうやったんですか?」「それAIがやったのでは?」「誰でも言えるのでは?」「で、あなたは何を判断したんですか?」）
  - 説得力が弱い・抽象的すぎる・裏づけがない・企業ニーズとずれている箇所を指摘させる
  - 各テーマで**一番効く追い質問**（候補者が詰まると痛い一撃）を1つ挙げさせる
- 出力フォーマット: 〔どの回答〕→〔何が弱いか〕→〔面接官ならこう突く〕のリスト

**レビューを受けて、メイン側で修正版を作る:**
- 弱い回答を、**経歴書の事実の範囲で**強くする
- 事実で強くできない弱点は、回答本体を盛らず、**追い質問への正直な備え**としてメモに足す
- 修正後も短文・自分の言葉を保つ（軸6）

> ⚠️ レビュアーは構造上「もっと強く見せろ」という圧をかけてくる。**修正は必ず軸4（誠実性）を上位に置く。** 盛って突っ込みを回避するのは禁止——突っ込みには正直な答えを用意する。レビューで上がった弱点が事実で埋まらないなら、それは「盛る」サインではなく「正直な備えを書く」サイン。

### 6. 出力

`output/applications/面接準備メモ_{企業名}_{ラウンド}_{YYYYMMDD}.md` に保存する。
冒頭に「0. 回答方針（自分への約束）」、末尾に「言ってはいけない言葉」と「面接官が突いてくる追い質問（正直な備え）」を必ず入れる。

## 出力テンプレート

```markdown
# 面接準備メモ｜{企業名} {ラウンド}（{YYYY-MM-DD}）

## 0. 回答方針（自分への約束）
- 盛らない。経歴書の事実から離れない。盛った瞬間に矛盾が生まれる。
- 自己評価を断定しない。事実を述べ、控えめに意味づけする。
- 表層の技術でなく、AI時代でも残る普遍的な強み（未知を構造化する／何を作るか決める／意思決定を前に進める）を軸に。
- 未経験・ギャップは隠さず、補い方とセットで。
- 結論から。短く、自分の言葉で。

## 1. 自己紹介（30秒）
- **{キーワードA}** — {1〜2文}
- **{キーワードB}** — {1〜2文}

- **{ギャップ}** — 正直に認める。＋ 補い方。

- ...

## 6. キャリア観・働き方
- **{テーマ}** — {1〜2文}

- 「特にありません」（思考停止）
```

## よくある失敗

| 失敗 | 直し方 |
|------|--------|
| 1問に4テーマ以上詰める | 最大3つに絞る。本番で思い出せない |
| 完全な語り原稿を書く | キーワード見出し＋短い語り口。暗記用の文章ではない |
| AI活用を「ツール利用」で止める | 「設計思想の組み替え」「事業価値への接続」まで言語化 |
| 表層の技術スキルだけで語る | その下の普遍的な強み（AI時代でも残る力）を軸にし、技術は表れとして添える |
| 自己評価を断定する（「これが私の価値」） | 事実を述べ、控えめに意味づけ。なぜそう言えるかを事実で支える |
| ポテンシャルを願望で語る | 領域・技術を越えて適応してきた事実で裏づける |
| 実績を盛る・断定する | 経歴書の事実のみ。データなしは「体感」と明示 |
| 書き言葉・過剰敬語になる | 短文・話し言葉・自分の言葉に（ただし断定の言い切りは避ける） |
| 志望動機が企業ニーズと結びつかない | 必ず募集要項×強みの重なりから導く |
| レビューをせず保存する | 保存前に面接官視点のサブエージェントレビューを必ず通す |
| レビュアーに規則チェックまでさせる | レビュアーは面接官視点だけ。盛り・書き言葉の検査は方針セクション任せ |
| 突っ込み回避のため盛って修正する | 軸4が最優先。事実で埋まらない弱点は「正直な備え」に変換する |
