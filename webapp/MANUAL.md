## 1. このツールが扱うもの

記録するのは3種類だけです。

| 種類 | 画面での呼び名 | 中身 |
|---|---|---|
| やりとり | 記録する / 見える化 | いつ・どうやって話し、**どう伝えたか** |
| やくそく | やくそく | そのやりとりで決まった、誰かがやること |
| 目標 | 目標 | いくつものやくそくが積み上がって届く、長期のもの |

やりとりから、やくそくが生まれます。やくそくは目標に紐づきます。
この3階層以外は持ちません。

**記録しないもの**（意図的に持っていません）

- 相手ができなかったことの一覧
- 相手の苦手なことの一覧
- 相手への点数や評価

入力欄にも、これらを書く場所はありません。
画面はいつか相手に見られます。見られて困るものを持たない、という設計です。

## 2. 準備する

### 2.1 必要なもの

| 必要なもの | 条件 | 確認方法 |
|---|---|---|
| Node.js | **20.6 以上** | `node -v` |
| git | 取得に使うだけ | `git --version` |

`npm install` は不要です。外部パッケージを1つも使っていません。

### 2.2 まず試す（架空のデータ入り）

```bash
npm run demo
```

`http://127.0.0.1:4173` を開くと、3週間ぶんの架空の記録が入った状態で全画面を見られます。

- サンプルは `/tmp/tsutae-log-demo.json` に作られます
- **本物の記録には一切触れません**。試したあとそのまま `npm start` すれば、空の状態から始まります

スマホからも見たい場合:

```bash
npm run demo -- --lan
```

起動時にスマホ用の URL（`http://192.168.x.x:4173` など）が表示されます。

### 2.3 本番を始める

```bash
npm start
```

記録は `data/tsutae-log/db.json` に貯まります。git 管理外です。

| 環境変数 | 既定値 | 意味 |
|---|---|---|
| `TSUTAE_PORT` | `4173` | 待ち受けポート |
| `TSUTAE_HOST` | `127.0.0.1` | `0.0.0.0` にすると同じネットワークの他端末から見える |
| `TSUTAE_DATA` | 自動 | 保存先ファイルを明示する |

`TSUTAE_DATA` を指定しない場合、次の順に**既にある記録**を探して引き継ぎます。
名前や置き場所を変えても記録が見えなくならないようにするためです。

1. `data/tsutae-log/db.json`（アプリ直下・既定）
2. `../data/tsutae-log/db.json`（他のワークスペースに同居している配置）
3. `../data/futari-log/db.json`（「ふたりログ」という名前だった頃）

2 か 3 を使った場合は、起動時にその旨が表示されます。

### 2.4 スマホから使う

1. パソコンで `TSUTAE_HOST=0.0.0.0 npm start`（または `npm run demo -- --lan`）
2. パソコンの LAN 内アドレスを調べる
   - macOS: `ipconfig getifaddr en0`
   - Windows: `ipconfig | findstr IPv4`
3. スマホのブラウザで `http://<そのアドレス>:4173` を開く

> **認証はありません。**
> 外に開いているあいだ、同じ Wi-Fi にいる端末からは誰でも中身を読めます。
> 自宅など、つないでいる人が分かっているネットワークでだけ使ってください。
> パソコンを閉じるとサーバーも止まります。

### 2.5 最初の設定

**設定**画面で、最低限これだけ決めます。

| 項目 | 既定 | 決め方 |
|---|---|---|
| 相手の呼び名 | 相手 | 画面と渡すカードに出ます。実際に呼んでいる名前にします |
| 自分の呼び名 | 自分 | 渡すカードの「◯◯がやること」に出ます |

しきい値は、しばらく使ってから調整すれば十分です（→ [4.7](#47-設定)）。

## 3. 毎日の手順

やることは3つです。慣れれば記録は30秒で終わります。

### 手順1 — 話したあと、すぐ記録する

1. **記録する**画面を開く
2. 「話した内容」を1〜2行書く（**これだけが必須**）
3. 「記録する」を押す

他の項目は空のままで保存できます。
調子や伝え方を必ず埋めようとすると、忙しい日から順に記録が途切れます。

> 余裕があるときだけ「使った伝え方」を選んでおくと、あとで
> 「どの伝え方が効いたか」が出せるようになります（→ [4.5](#45-見える化)）。

### 手順2 — 決まったことを切り出す

記録する画面の下半分、「この話で決まったこと」で、同じ画面のまま追加します。

1. 「＋ やくそくを足す」を押す
2. **何をする**を書く（例: 区役所に電話する）
3. **だれが**を選ぶ（相手 / 自分 / いっしょに）
4. **いつまで**を決める（「今日」「明日」「3日後」「来週」のボタンが使えます）
5. 必要なら**手順**を1行1動作で書く

> 日付は必ず決めてください。日付のない依頼は実行されません。
> その場で決められない場合も、仮の日付を置いて後から動かすほうが残ります。

### 手順3 — カードを作って渡す

1. **渡すカード**画面を開く
2. 「つぎに話す日」を決める
3. 「コピー」または「印刷」

出てくるのは、相手が読むための短いテキストです。

- できたことが先に来ます
- お願いは**上限件数まで**（既定3件）。超えたぶんは載りません
- **過ぎた日付は一切書かれません**（「いっしょに日にちを決める」に置き換わります）

## 4. 画面リファレンス

### 4.1 今日

朝か、相手に会う前に開く画面です。

**まだ記録が1件もないとき**は、代わりにこのツールの立て付け（何を記録し、何を記録しないか）と伝え方の約束が表示されます。

**記録があるとき**の構成:

| 要素 | 意味 |
|---|---|
| 大きな数字 | 今日、相手に声をかける件数（上限件数まで） |
| 期限切れ | 決めた日を過ぎた件数 |
| 今日が期限 | 今日が期日の件数 |
| お願いしていること | 相手が担当の未完了件数。上限を超えると赤くなります |
| ◯◯がやること | 自分が担当の未完了件数 |
| 最後の記録 | 直近の記録からの日数。途切れると赤くなります |
| 連続記録 | 何日続けて記録しているか |

**抜け漏れチェック** — 出ている警告と対処は [7章](#7-警告の一覧と対処) にまとめています。
「該当をみる →」で、対象のやくそくに絞り込んだ一覧へ飛びます。

**次に話すこと** — 緊急度順に上限件数まで。各項目には:

- **言い方** — そのまま口に出せる一文。日付を過ぎた件でも、できていない事実には触れません
- **まず:** — 手順がある場合、最初の1つだけ
- ボタン3つ — 「できた」「伝えた」（伝え直しを1回数える）「言い方をコピー」

末尾に**伝え方の約束**が畳んであります。言い方を選ぶ直前に目に入る位置に置いています。

### 4.2 記録する

| 項目 | 必須 | 内容 |
|---|---|---|
| 話した内容 | **○** | 1000文字まで。主語は自分にする（→ [6章](#6-記録の書き方)） |
| いつ | | 既定は現在時刻。あとから入力するときは変える |
| どうやって | | 対面 / LINE・チャット / 電話 / その他 |
| その日の様子 | | 1〜5。評価ではなく「重い話をしていい日か」の目印。もう一度押すと解除 |
| 伝わったかの確認 | | 確認していない / 「わかった？」と聞いた / 相手の言葉で言い直せた |
| 話のかみ合い（伝わりぐあい） | | すんなり通った / すこし伝わりにくかった / うまく伝えられなかった |
| 使った伝え方 | | 8種類から複数選択（→ [10.1](#101-選択肢の一覧)） |
| 関係する長期目標 | | 目標を登録していると選べます |
| メモ | | 折りたたみ。2000文字まで |

**「伝わったかの確認」を3段階にしている理由**

「わかった？」への「わかった」は、伝わった証拠になりません。
相手の言葉で言い直せたところまで行って、はじめて伝達と数えます。
この区別が、あとで「効いた伝え方」を出すときの軸になります。

### 4.3 やくそく

未完了を上から片付けていく画面です。

**並び順** — 緊急度の高い順に自動で並びます。

1. 日付を過ぎたもの（過ぎた日数が多いほど上）
2. 今日が期日
3. 期日が近い（3日以内）
4. 期日が先
5. 日付未定（放置が長いほど上）

さらに、一定日数動いていないもの、伝え直しが2回以上のものが上に寄ります。

**絞り込み** — 未完了 / 期限切れ / 今日・明日 / 期限なし / 相手 / 自分 / 完了

**各カードの操作**

| ボタン | 何が起きるか |
|---|---|
| できた | 完了にする。完了日が記録され、渡すカードの「できたこと」に載る |
| もう一度伝えた | 伝え直しを1回数える。3回を超えると警告が出る |
| 日付欄 / 今日・明日・3日後・来週 | 期日を変える |
| **こちらで預かる** | 担当を自分に移す。渡しすぎたときの逃がし方 |
| 相手にお願いする | 担当を相手に移す（自分担当のときに出る） |
| やめる | 取り下げる。確認が出ます |

手順のチェックボックスは、押すとその場で保存されます。

> **「こちらで預かる」を使う場面**
> 「お願いを4件ためています」と出たら、いちばん急がない1件をこちらに移します。
> 数を減らさずに催促を重ねても、結局どれも進みません。

**やくそくを直接足す** — 画面下部から、やりとりの記録なしで追加できます。
思い出したその場で入れるためのものです。

### 4.4 目標

| 要素 | 意味 |
|---|---|
| 進捗バー | 一歩（マイルストーン）の完了率。一歩を登録していない場合は、紐づくやくそくの完了率 |
| 停滞バッジ | 既定30日、紐づく動きがないと出ます |
| ◯日前に動き | 最後に関連する記録・完了があった日からの日数 |
| 次の一歩 | 未完了の一歩のうち、いちばん上の1つだけ |

**登録するとき**

- **目標** — 例: ひとり暮らしの準備を終える
- **なぜ大事か** — 相手の言葉のまま書きます。迷ったときの判断材料になります
- **いつまで** — 任意
- **一歩に分ける** — 1行に1つ。20個まで。大きいままだと手がつきません

一歩は、カードの入力欄から Enter でいつでも足せます。

### 4.5 見える化

読む相手は記録している側だけです。相手には渡しません。
どのグラフにも「表で見る」が付いていて、数字で読み直せます。

| グラフ | 期間 | 読み方 |
|---|---|---|
| 記録した日 | 直近12週 | 色が濃いほどその日の記録が多い。空白が続いていたら記録が途切れている。クリックするとその日の記録に飛ぶ |
| その日の様子 | 直近60日 | 線は7日平均、点は記録があった日。1=疲れていそう 〜 5=元気そう |
| 未完了のやくそくの古さ | 現在 | 0〜2日 / 3〜6日 / 7〜13日 / 14日以上。棒をクリックすると該当の一覧へ |
| 伝え方の効き目 | 全期間 | 工夫を**した回**と**しなかった回**の完了率の比較 |

**「伝え方の効き目」の見方**

- 母数は**決着したやくそく**（完了または取り下げ）だけです。まだ進行中のものは入りません
- やりとりの記録から切り出したものだけが対象です（直接足したやくそくは入りません）
- **「した」「しなかった」がそれぞれ3件以上ないと、判定を出しません**

3件未満のときは「まだ判断できません」と表示されます。少ない件数の差を根拠にすると、
効いていないやり方を「効いている」と思い込んで続けることになるためです。

**週のふりかえり** — 「ふりかえりを作る」を押すと、そのまま人に共有できる形のテキストが出ます（→ [5章](#5-週に一度の手順)）。

**やりとりの履歴** — 新しい順に20件。カレンダーから飛んだ場合はその日だけ表示されます。

### 4.6 渡すカード

このツールで唯一、相手が読むものです。

| 設定 | 効果 |
|---|---|
| つぎに話す日 | カードの末尾に入ります。空でも構いません |
| ◯◯がやることも載せる | 自分の担当分を載せるかどうか |

**カードの構成**

```
9月19日(土)  ゆうへ

【できたこと】
・燃えるゴミを朝に出す（9月17日）

【おねがい】
1. 不動産屋に「第2土曜で」と電話する
   いつまで: （いっしょに日にちを決める）
   - 月曜の朝に電話する
   - 「第2土曜に入りたい」と言う

【自分がやること】
・薬局に処方せんを出す（9月23日まで）

つぎに話すのは 9月24日(木)
わからなくなったら、この紙を見せて聞いてください。
```

**載るもの・載らないもの**

| | 規則 |
|---|---|
| できたこと | 直近7日に完了したもののうち3件まで。自分だけの担当だったものは載りません |
| おねがい | 緊急度順に上限件数（既定3件）まで |
| 手順 | 未完了のものだけ、各4つまで |
| 過ぎた日付 | **載りません。**「（いっしょに日にちを決める）」に置き換わります |

載せきれなかった件数は、画面側にだけ注記が出ます。

> **なぜ過ぎた日付を出さないか**
> 「9月18日をすぎています」と書かれた紙は、渡した瞬間に責めている紙になります。
> その紙自体が嫌なものになると、次から受け取ってもらえません。
> 経過日数は記録している側の画面に残るので、情報は失われていません。

### 4.7 設定

**呼び名** — 相手・自分。画面と渡すカードに反映されます。

**しきい値**

| 項目 | 既定 | 何が変わるか | 上げる / 下げる目安 |
|---|---|---|---|
| 一度に渡す上限 | 3件 | 「渡しすぎ」警告、次に話すことの件数、カードに載る件数 | 相手が余裕をもって捌けているなら上げる。落ちるものが多いなら下げる |
| 「止まっている」とみなす日数 | 7日 | 放置の判定、「伝わったか未確認」警告 | やりとりの頻度が低い関係なら長くする |
| 「連絡が途切れた」とみなす日数 | 4日 | 記録が途切れた警告 | 毎日会う関係なら短く、週1なら8日など |
| 目標が「停滞」とみなされる日数 | 30日 | 目標の停滞バッジと警告 | |
| 期限なしを催促するまでの日数 | 3日 | 「期限のないやくそく」警告 | |

すべて1〜365の範囲です。保存を押すまで反映されません。

**バックアップ** — [9章](#9-データとバックアップ) を参照。

**いまの中身** — やりとり・やくそく・目標の件数。

この画面の下部には、このツールの立て付け（記録するもの / しないもの）と伝え方の約束が常設されています。

## 5. 週に一度の手順

**見える化**画面の「ふりかえりを作る」を押すと、次の内容が Markdown で出ます。

1. **今週の数字** — 記録した日・やりとり・新しいやくそく・完了・その日の様子の平均（先週と並べて）
2. **できたこと** — 今週完了したやくそく
3. **気になっていること** — 出ている警告
4. **次に話すこと** — 言い方つき
5. **長期目標** — 進捗と停滞
6. **伝え方の効き目** — 件数が足りていれば数字で

週の区切りは**月曜〜日曜**です。

おすすめの手順:

1. ふりかえりを作ってコピーする
2. 「気になっていること」に出ている警告を、その場で片付ける
   - 期限切れ → 日付を決め直す
   - 渡しすぎ → 1件「こちらで預かる」
   - 期限なし → 日付を入れる
3. 目標が停滞していたら、次の一歩を1つだけ決める
4. 渡すカードを作って渡す

## 6. 記録の書き方

自由記述（話した内容・メモ・やめた理由）には、**相手が読んで傷つく言葉を書かない**でください。

画面はいつか覗かれます。そのとき傷つく言葉が書いてあると、このツールごと使えなくなります。

| 書かない | こう書く |
|---|---|
| また忘れてた | 口頭だけで伝えた。文字にしていない |
| 話が通じない | 一度に3件渡した。1件目しか残らなかった |
| やる気がない | 日付を当日に置いた。取りかかる時間がなかった |

**主語を自分にすると、記録がそのまま次に直す場所になります。**
右側の書き方は我慢や建前ではなく、単に精度が高いというだけです。
左側は原因を人に置いて止まりますが、右側には次の手が書いてあります。

記録する画面の「書き方に迷ったら」を開くと、この表がその場で読めます。

## 7. 警告の一覧と対処

「今日」画面の**抜け漏れチェック**に出るものの全部です。

| 表示 | 出る条件 | 対処 |
|---|---|---|
| ■ 日付が過ぎたものが◯件 | 期日を過ぎた未完了がある | 催促しない。「いつやる？ 今日と明日ならどっち？」で日付を決め直す |
| ▲ お願いを◯件ためています | 相手担当の未完了が上限を超えた | いちばん急がない1件を「こちらで預かる」。または日付を先に延ばす |
| ▲ 同じことを3回以上伝えているものが◯件 | 伝え直しが3回以上 | 回数を増やさない。手順に割る・日付を変える・こちらでやる、のどれかに切り替える |
| ▲ ◯日、やりとりの記録がありません | 最後の記録から既定4日以上 | 短くていいので記録を1件入れる |
| ▲ ◯日以上動いていない目標が◯件 | 既定30日、目標に紐づく動きがない | 次の一歩を1つだけ決める |
| ● 今日が期限のやくそくが◯件 | 今日が期日 | 今日のうちに声をかける |
| ● 期限のないやくそくが◯件 | 日付未定のまま既定3日以上 | 具体的な日付を決めて、日付で伝える |
| ● 伝わったか確かめていないものが◯件 | 相手の言葉で戻ってきておらず、既定7日以上動いていない | もう一度短く伝えて、言い直してもらう |
| ● まだ記録がありません | 記録が0件 | 1件入れる |
| ✓ 今日の抜け漏れはありません | 上記がすべて該当しない | — |

## 8. 困ったとき

### 起動しない

| 症状 | 原因と対処 |
|---|---|
| `SyntaxError` や `Unexpected token` が出る | Node が古い。`node -v` で 20.6 以上を確認 |
| `EADDRINUSE` | ポート4173が使用中。`TSUTAE_PORT=4180 npm start` |
| `Cannot find module` | リポジトリのルートで実行しているか確認（`package.json` のある場所） |

### スマホから開けない

1. `TSUTAE_HOST=0.0.0.0` を付けて起動しているか
2. パソコンとスマホが**同じ Wi-Fi** か（スマホが4G/5Gになっていないか）
3. パソコンのファイアウォールがポートを塞いでいないか
4. 表示されたアドレスを正確に入力しているか（`127.0.0.1` ではなく `192.168.x.x`）

### 記録が見当たらない

保存先が切り替わっている可能性があります。起動時のログに実際のパスが出ます。

```
つたえログ
  画面      http://127.0.0.1:4173
  データ    /path/to/data/tsutae-log/db.json   ← ここを確認
```

`npm run demo` で起動した場合は `/tmp/tsutae-log-demo.json` を見ているので、
本物の記録は表示されません。`npm start` で起動し直してください。

### 「保存ファイルが壊れていたため退避しました」と出た

JSON として読めない状態になっていました。元のファイルは
`db.json.broken-<時刻>` という名前で**消さずに残して**います。
中身を直せば、そのファイル名を `db.json` に戻して復旧できます。

### 画面が真っ白 / 「読み込みに失敗しました」

サーバーが止まっている可能性があります。ターミナルを確認してください。
ブラウザのコンソールにエラーが出ていれば、そのまま報告してください。

## 9. データとバックアップ

### 保存のしかた

- 記録は**1つの JSON ファイル**です
- 書き込みは一時ファイルを作ってから置き換えます（途中で電源が落ちても半端なファイルになりません）
- 同時に複数の更新が来ても、順番に処理されます

### 書き出し

**設定 → バックアップ → JSONで書き出す**

`tsutae-log-YYYY-MM-DD.json` という名前で保存されます。

### 読み込み

**設定 → バックアップ → JSONから読み込む**

> **読み込むと、いまの記録はすべて置き換わります。** 確認が1回出ます。
> 追記ではありません。

### 勧めること

ローカルのファイルなので、消えるときは静かに消えます。
**月に1度は書き出して、別の場所に置いておいてください。**

### 外部に出ないこと

- 外部サービスへの通信は一切しません
- ブラウザ側も、ページ自身以外への通信を禁止しています（CSP）
- 既定では、このパソコンからしか開けません

## 10. 付録

### 10.1 選択肢の一覧

**どうやって（channel）**

| 値 | 表示 |
|---|---|
| `face` | 対面 |
| `line` | LINE・チャット |
| `phone` | 電話 |
| `other` | その他 |

**その日の様子（condition）**

| 値 | 表示 |
|---|---|
| 1 | かなり疲れていそう |
| 2 | すこし疲れていそう |
| 3 | ふつう |
| 4 | 落ち着いている |
| 5 | 元気そう |

**伝わったかの確認（understanding）**

| 値 | 表示 |
|---|---|
| `none` | 確認していない |
| `asked` | 「わかった？」と聞いた |
| `readback` | 相手の言葉で言い直せた |

**伝わりぐあい（friction）**

| 値 | 表示 |
|---|---|
| `none` | すんなり通った |
| `some` | すこし伝わりにくかった |
| `hard` | うまく伝えられなかった |

**使った伝え方（techniques）**

| 値 | 表示 | ねらい |
|---|---|---|
| `one_at_a_time` | 1回に1つだけ伝えた | 一度に渡す量を減らす |
| `written` | 書いて渡した | 口頭だけにしない |
| `steps` | 手順に分けた | 1手順=1動作まで割る |
| `concrete_date` | 期限を具体的な日付で言った | 「早めに」を使わない |
| `no_rush` | 急かさず待った | 処理の速さの差を時間で埋める |
| `choice` | 選択肢を2つに絞った | 自由回答より決めやすい |
| `praise` | できたことを先に認めた | 否定から入らない |
| `quiet_place` | 静かな場所で話した | 注意がそれる要因を減らす |

「伝え方の効き目」では、これに加えて `readback`（相手の言葉で言い直してもらった）が
比較対象に入ります。

**だれが（owner）**

| 値 | 表示 |
|---|---|
| `partner` | 相手（設定した呼び名） |
| `me` | 自分（設定した呼び名） |
| `both` | いっしょに |

### 10.2 入力の上限

| 項目 | 上限 |
|---|---|
| 話した内容 | 1000文字 |
| やくそく・目標・一歩のタイトル | 200文字 |
| メモ・やめた理由 | 2000文字 |
| なぜ大事か | 1000文字 |
| 手順 | 12個 / 1つ200文字 |
| 一歩（マイルストーン） | 20個 |

手順を12個までにしているのは、それ以上に割ると渡された側が追いきれないためです。

### 10.3 API

外部から読み書きするための口です（`http://127.0.0.1:4173` 配下）。

| メソッド | 経路 | 用途 |
|---|---|---|
| GET | `/api/state` | 全データ＋集計 |
| GET | `/api/insights` | 集計のみ |
| GET | `/api/options` | 選択肢の一覧 |
| GET | `/api/handoff?nextTalkDate=YYYY-MM-DD&includeMine=false` | 渡すカード |
| GET | `/api/review?format=markdown` | 週次ふりかえり |
| GET | `/api/export` | バックアップ用 JSON |
| POST | `/api/interactions` | やりとり（やくそく同時作成可） |
| PATCH / DELETE | `/api/interactions/:id` | やりとり |
| POST | `/api/commitments` | やくそく |
| PATCH / DELETE | `/api/commitments/:id` | やくそく |
| POST | `/api/goals` | 目標 |
| PATCH / DELETE | `/api/goals/:id` | 目標 |
| PATCH | `/api/settings` | 設定 |
| POST | `/api/import` | 全置き換え |

書き込み系は、別オリジンからのリクエストを拒否します。

例（やりとりとやくそくを同時に作る）:

```bash
curl -s -X POST http://127.0.0.1:4173/api/interactions \
  -H 'Content-Type: application/json' \
  -d '{
    "summary": "引っ越しの日を相談した。紙に書いて渡した",
    "channel": "face",
    "understanding": "readback",
    "techniques": ["written", "concrete_date"],
    "commitments": [
      { "title": "不動産屋に電話する", "owner": "partner", "due": "2026-10-05" }
    ]
  }'
```

### 10.4 用語

| 語 | 意味 |
|---|---|
| やりとり | 1回の接触の記録。この単位で「どう伝えたか」が残る |
| やくそく | 誰かがやること。未完了 / 完了 / 取り下げ の3状態 |
| 決着した | 完了または取り下げになったもの。「伝え方の効き目」の母数 |
| 緊急度 | やくそくの並び順を決める内部の点数。期日・放置日数・伝え直し回数から算出 |
| 渡すカード | 相手が読む短いテキスト。このツールで唯一、相手の目に入るもの |
| 伝え方の約束 | 伝える側が守る5つのこと。相手に課すルールは作らない |

### 10.5 開発者向け

```bash
npm test     # node:test。外部依存なし
npm run dev  # ファイル変更で再起動
```

集計は `server/insights.js` が1回で出します。画面側で数え直しません。
数える場所を増やすと「ダッシュボードでは3件、カードでは2件」というずれが起きます。
